## Receipts and promotion

For each run preserve task and harness hashes, snapshot and plugin hashes, CLI version, requested and actual model, effort, start/end timestamps, authoritative exit, grader exit, tokens by input/cache-create/cache-read/output, total tokens, wall time, load samples and trace hash. Keep raw traces private. Public results contain sanitized aggregate data only.

Compute equal-task-weight pass rate over complete paired cells. Use all valid pass, fail and timeout outcomes for token cost, including unsuccessful attempts. Do not compare only successful runs. Keep contamination, billed API, missing stream and unavailable process-table rows visible in an excluded-evidence table. Unknown or loaded machine state cannot supply quiet wall time. Re-run the affected paired cell on a quiet host before using its latency for promotion.

The current frontier.js prints several pairwise Pareto sets. Those charts alone do not implement the required three-axis decision. Derive a joint table from its run rows: pass rate to maximize, total tokens and median quiet wall time to minimize. Arm X dominates Y only when X is no worse on all three and strictly better on at least one. A promotion must be on the joint frontier, strictly improve at least one aggregate axis versus A rather than duplicate an existing point, satisfy the experiment-specific threshold, retain every critical rejection control and have all eight task cells at k>=3. Plot all arms including failures. k=3 is an exploratory floor, not a strong statistical confidence claim. Repeat disputed cells before any default change.

Record no-winner if missing model evidence, an invalid grader, insufficient quiet samples or an incomplete task matrix prevents a decision. Do not widen answer keys after seeing outputs. If a key is wrong, invalidate the fitted rows, version the correction and rerun all affected arms.

## Cost estimate and stop conditions

The full design is 96 model/effort runs and 48 runs in each snapshot experiment, 192 runs total. A k=1 smoke stage has 64 runs. These are planning estimates, not a measured bill.

Budget 5k to 25k uncached input tokens, 50k to 250k cached input tokens and 2k to 8k output tokens per run. That gives approximately 10.9M to 54.3M total tokens across 192 runs, including 384k to 1.54M output tokens. At 5 to 20 minutes per run, allow 16 to 64 sequential agent hours plus plant and grading time. The manifest timeout ceilings sum to 265 minutes per eight-task sweep, or 106 hours over the complete design before grading overhead. Calibrate estimates with the first paired smoke sweep, record subscription utilization and reported notional cost, and stop before exceeding the existing 0.70 utilization ceiling. Do not convert configured model names into current dollar prices without a verified rate and actual-model receipt.

Radar evidence motivates caution. Concise handoffs and forced global subagent selection had no-winner results. Native plugin evals lacked sufficient surviving evidence. RADAR-001 favored an explicit scoped git diff, already present in verification guidance. RADAR-002 native prompt audit missed all three planted defects and produced an unsupported finding. This preregistration tests bounded variants rather than treating those features as universal improvements.
