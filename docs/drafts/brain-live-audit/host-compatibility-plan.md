## Minimal host-specific proposal

1. **Admission before dispatch.** Persist a separate capability result keyed by exact executable/version, platform, selected package artifact hashes, loaded manifest paths and trusted-definition identity. Parse errors or unsupported mandatory capabilities leave `harness-compatible=false` even when the code task succeeds. A worker must not inherit protection claims from source presence or installed plugin names.
2. **Separate Codex packaging/configuration, preserve Claude source.** Prefer a Codex-specific manifest selection or generated Codex distribution that references a supported hooks configuration; keep the Claude `modules` declaration and function-hook implementation intact. First prove the native host's manifest selection on this version. If host metadata selection is unavailable, use a separately generated host artifact rather than mutating the common installed cache. A command-only Codex projection must explicitly list absent function-hook protections, and missions requiring them remain unadmitted until an actual equivalent exists. Do not copy the Claude session vault into a subprocess and call it equivalent.
3. **Commands and payload adapters need semantic tests.** Resolve the exact versioned handler schema and runner: determine whether `args` is recognized, rejected or ignored before converting anything. If only a shell command is supported, generate a fixed reviewed wrapper invocation with tested path quoting; never concatenate mission text into a shell. Test native Bash/apply_patch tool naming, tool-input fields, output decisions and context attachment. Keep unsupported events out of the Codex projection with an explicit capability gap; do not silently drop them while reporting compatibility.
4. **SessionEnd stays bounded.** A declaration of timeout 3 removes a clamp warning but is not evidence of reliable memory completion. Measure representative synthetic finalization within the actual host budget, including a slow/failure control. If it cannot finish reliably, design a durable bounded producer plus separately supervised processing with visible completion; do not convert it blindly to async or increase a timeout the host clamps. The store/result transport drafts remain unactivated and do not supply this integration automatically.

## Actual test oracle for the next isolated implementation

Use the version-pinned native hook schema/parser and runner, not a second hand-written schema. The official source bundle includes `hooks/src/schema.rs`, `engine/schema_loader.rs`, `engine/command_runner.rs`, configuration rules and native SessionEnd tests. Run its existing native parser/loader tests or expose that same parser through a small test harness against disposable plugin copies. First establish a supported no-model fixture entrypoint; this pass did not assume that help or JSON-schema generation executes hooks.

For native admission/discovery, inspect the exact app-server `hooks/list` protocol/tests included in the saved sources. Require a nonempty expected hook population, selected file/hash and trust/availability state; discovery alone is not execution. Use a disposable explicitly scoped test configuration/host for later runs, never the current installed cache or live memory. Any initialization or trust change belongs to that test host and must be reported.

For actual execution, use synthetic canary hooks that record invocation ID, event, native payload shape, cwd, plugin root and owned fixture artifact, without logging prompts or credentials. Verify the native runner invokes the expected script (not merely `node`), respects paths with spaces, propagates a blocking decision before the protected side effect, and handles failure/nonzero/invalid output. A different marker or removed hook must fail the expected assertion; a separate valid allowed action is the positive control. For tool payloads, drive an actual native apply_patch path and assert the post-edit check sees its changed file. A Bash-only canary does not cover edits.

Timeout oracle: one short successful SessionEnd canary plus one deliberately over-budget canary; record elapsed time, host termination and persisted completion marker. Never report a killed finalizer as a completed memory write. The rollback/control fixture must prove prior stored data survives.

Differential packaging oracle: unchanged Claude function-hook registrations and existing function suites remain positive; Codex host projection passes its native parser with no unsupported mandatory handler or clamp diagnostics. One invalid `modules` fixture must reproduce the native rejection. Native command receipts, artifact/state assertions and meaningful negative controls are all required before setting compatibility true.
