## spawn-budget: reds on a correct module under load, and "killed" for a child that never ran

Two problems in `tooling/spawn-budget.js`, both seen in gate logs.

1. Checks that spawn a node child, let it write and then kill it on a
   sub-second timeout go red on a correct module under load
   (`ETIMEDOUT stdout=""`): the kill landed before node started. A 48 ms idle
   child once took over 1000 ms to start. A bigger budget only moves the spike
   size it takes. An attempt killed before its child wrote says nothing about
   the claim and must not grade red. If no attempt gets that far, the case is
   INDETERMINATE (exit 2), never FAIL.
2. `lastWords()` says "the child wrote nothing before it was killed" for any
   empty result, even a planted ENOENT that never started, or a silent exit.

## Interface the checks use

- New export `untilWrittenBeforeKill(attempt, readyFile, baseMs)`. `attempt(ms)`
  runs the child once under a kill budget of `ms` and returns its spawnSync
  result. The child creates `readyFile` after its output, before it hangs.
  `baseMs` is the usual budget. Returns `{ r, verdict, trail }`: `r` is the
  attempt to grade, `verdict` is false only when no attempt got the child to
  write before its kill, `trail` is one line describing the attempts.
- `lastWords` on empty streams always contains `wrote nothing`, and says
  `killed` only for a timeout or signal, `never started` for a failed spawn,
  `exited` for a numeric exit status.
- `--selftest` prints undecided cases as `INDETERMINATE` lines, adds
  `, N indeterminate` to its `population:` line, and then exits 2 if none failed.
- Spawns are counted by replacing `child_process.spawnSync` on the module
  object, so `runBudgeted` must keep calling it through that object.
