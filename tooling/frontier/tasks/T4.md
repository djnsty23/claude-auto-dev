## The release gate can never pass before a push

`tooling/check-runtime.js` (`npm run check:runtime`) compares the installed
plugins against the source and fails when their versions differ. At release
time the source is always ahead of the install, because the new version has
not been pushed yet, so chaining this check into `gate:release` guarantees a
red at the one moment that gate must be run.

Add a `--pre-release` flag to `check-runtime.js`, and run it with that flag
from `gate:release` in `package.json`.

Correct behaviour with `--pre-release`:

- An install merely behind the source is not a failure. Both the marketplace
  clone line and the active pin line are logged at `[INFO]` instead of
  `[FAIL]`, and the pin line still says `active pin is <version>`.
- An install ahead of the source still fails, and so does every other
  mismatch, because then the code that runs is not the code that was edited
  and no push fixes it.

Without the flag, every result is exactly what it is today.
