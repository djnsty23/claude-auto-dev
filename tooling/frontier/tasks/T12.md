## supabase-types-stale fires on a complete types file

The security gate's `supabase-types-stale` rule, in
`plugins/autodev-core/scripts/security-checks.js`, compares the tables the
migrations create with the tables the generated Supabase types file names. It
reports every migration table the types file lacks.

A project ran its types file through a formatter that collapsed it onto fewer
lines. The file still named every table, and the rule reported every table as
missing.

Correct behaviour: a table key counts wherever the types file puts it, at the
start of a line or after `{`, `;` or `,` on a compacted line. A file that
really lacks a table still fires, and a project with no types file stays
silent.
