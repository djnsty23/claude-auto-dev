## A criterion that waits on the owner crashes the scorecard

`tooling/scorecard.js` grades the criteria in `docs/scorecard-criteria.json`
from probe receipts. The `credential-boundary` criterion names a probe file
that was never written, because its work was declined by the owner on
2026-09-23. Every receipt for it fails with MODULE_NOT_FOUND, and a receipt
from some other probe could make it read PASS while the decision still stands.

Add a criterion kind for this, exported from `scorecard.js` as `OWNER_HELD`
with the value `'owner-held'`. It is not a strength of evidence, so it stays
out of `KINDS`.

Correct behaviour:

- `criterionStatus` grades an owner-held criterion `OWNER_HELD` whatever
  receipts exist, fresh operational PASS receipts included, with `why` set to
  `owner-held: ` followed by the criterion's `needs`.
- An owner-held criterion counts zero towards its aspect's score, as UNKNOWN
  does, and keeps its weight.
- `validateManifest` reports one problem for an owner-held criterion with no
  `needs` text, and one for an owner-held criterion that has a `probe`.
- `record` refuses an owner-held criterion: it exits 2 and writes no receipt.
- In `docs/scorecard-criteria.json`, `credential-boundary` becomes owner-held,
  with no probe and `needs` set to `Andy reopens N5 (declined 2026-09-23)`.

Every other criterion grades exactly as before.
