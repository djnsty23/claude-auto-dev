## headless-worker: a record whose supervisor died can never be settled

After a reboot, four records in the ledger of `plugins/autodev-core/scripts/headless-worker.js`
stay unsettled for good. Their supervisors died, so no log got a `CLAUDE_EXIT`
line, `settle` refuses them with `not-exited`, and `status` lists them forever.

Wanted: `settle --code X --lost` settles such a record as lost, only when it is
provably not running. A record started before this boot qualifies whatever its
pid says now, since a pre-boot pid can name a stranger. One started after this
boot qualifies only when its recorded pid is dead. An alive pid, or no pid, is
no proof. A record whose log has an exit line ended normally: `--lost` refuses
it and plain `settle` still takes it. Lost is its own result, never done,
stopped or failed. A RESULT line in the report, if any, keeps its sentence.

## Interface the checks use

- Refusals use error code `not-lost`, and the exit-line one says to settle it
  `without --lost`. Unknown or already-settled codes stay `unknown-code`.
  Plain settle's `not-exited` message mentions `settle --lost`.
- Success value: `state: "lost"`, `reason`, `exit: null`, `settledAt`. A pre-boot
  reason starts `started <startedAt>` and contains `before this boot`. A dead-pid
  reason contains `pid <pid> is dead`.
- The ledger record becomes `state: "settled"`, `result: "lost"`, with `reason`,
  `settledAt`, `sentence` and `reportResult` (the RESULT line's state, or null).
- `status --json` records gain `settledAs` (a settled record's result, null while
  unsettled) and `lostReason` (a lost record's reason, else null). The text line
  appends ` settledAs=lost (<reason>)` right after `settled=true`, for lost only.
- `--help` lists `settle --code <CODE> [--lost]`, plus a line starting
  `settle --lost:` whose text says when it is refused, using `Refused unless`.
