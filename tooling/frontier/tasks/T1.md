## The tool-declaration gate passes on a skill it could not read

`tooling/check-skill-tool-declarations.js` scans every plugin `SKILL.md` for
tools the skill tells the model to use that its `allowed-tools` does not
declare. `scan()` returns the files it discovered, the results it read, and
the errors it hit.

Three defects:

1. `--selftest` ignores discovery and read errors. With one `SKILL.md`
   unreadable beside a readable one, the selftest still exits 0, while the
   normal gate fails closed.
2. The summary line `N skills scanned` counts skills discovered, not skills
   read, so a skill whose file read failed is counted as scanned. The
   empty-scan refusal (`read 0 skills, so nothing was checked`) has the same
   problem.
3. The CLI calls `process.exit()` with its result, which can cut off queued
   stdout and stderr when the output is piped and slow to drain.

Correct behaviour:

- The selftest fails, and prints each unreadable input as
  `NOT CHECKED: <file> (<code>)`, unless discovery had no errors and every
  discovered skill produced a result. Its readable-skill checks still run and
  still pass.
- The summary and the empty-scan refusal count skills actually read.
- The CLI sets `process.exitCode` and lets output drain, so every diagnostic
  reaches a pipe or a file, and the exit status is unchanged.

The findings themselves, `--advisory` and every exit code for a complete scan
stay as they are.
