## A heredoc that forbids --no-verify asks as if it used it

`plugins/autodev-core/scripts/hook-bypass.js` decides whether a Bash command
may bypass git hooks, and asks the user when it might. A worker wrote a brief
file with two heredocs. One body line, deep in the first heredoc, said "never
-m, never --amend, never --no-verify". The command asked for permission, as if
it pushed with `--no-verify`.

Heredoc bodies are argument text, not shell. A heredoc whose body is one line
is already treated that way. A body of several lines is not: lines after the
first are read as shell.

Correct behaviour: a heredoc body runs to its delimiter line, whatever its
length, and none of it is a git call. A real git call after the delimiter
still asks. A heredoc with no delimiter line runs to the end of the command,
and a git call before it still asks.
