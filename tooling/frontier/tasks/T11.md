## worktree-reap keeps every idle worktree after a git gc

`plugins/autodev-core/scripts/worktree-reap.js` removes a linked worktree only
when its work landed and it has been idle for the idle window. The nightly
cleanup runs `git gc` just before the reaper. On one machine, 180 of 415
worktrees were kept as active for one reason, and every logged run removed 0.

`git gc` expires reflogs, and that rewrites `logs/HEAD` in every linked
worktree's admin directory, whether or not anyone worked there.

Correct behaviour: the idle clock dates `logs/HEAD` by the newest entry time
written inside it, not by the file's modification time. A reflog with no
entry that parses falls back to its modification time, so an unreadable file
still keeps the worktree. HEAD and index keep their modification times, since
gc does not rewrite them.

## Interface the checks use

- The module exports `reflogMs(file)`: the newest entry time in the reflog at
  `file`, in milliseconds, or null when no line parses or the file is absent.
