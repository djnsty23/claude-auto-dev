feat: v7.5 — telemetry hook + skill (closes audit finding 3.2)

Local-first telemetry with optional OTLP forwarding. Closes the last
major audit finding ("No OTEL / telemetry — industry standard in 2026").

### Added
- hooks/telemetry.js — PostToolUse hook. Appends one JSONL line per
  tool call to .claude/reports/telemetry-YYYY-MM-DD.jsonl.
  Metadata only: tool name, input/output sizes, cwd, session,
  timestamp, success heuristic. NO tool input/output contents
  (privacy by design). Exit 0 always. 39ms end-to-end locally.
- skills/telemetry/ — read-side skill. Commands: `telemetry`,
  `usage stats`. Reports top tools, per-day activity, week view.
  Runs on Haiku.
- scripts/test-telemetry-hook.js — 15-case test suite.
  15/15 pass.

### Optional upstream export
Set CLAUDE_OTEL_ENDPOINT=<url> to also POST each event as OTLP JSON.
Works with Honeycomb free tier, local OTEL collectors, Jaeger, etc.
Fire-and-forget, 500ms HTTP timeout — unreachable endpoints never
block the session.

### Opt-out
Set CLAUDE_TELEMETRY_DISABLED=1 or remove the hook entry from
~/.claude/settings.json.

### Registered
Added a second PostToolUse entry (matcher: .*) to both
settings.json and settings-unix.json. Existing Write|Edit
typecheck entry unchanged.

### Why local-first
Zero-config day one. No account signup. No vendor lock-in. OTLP
export is opt-in so anyone who wants cloud aggregation (Honeycomb,
Datadog) can wire it without code changes.
